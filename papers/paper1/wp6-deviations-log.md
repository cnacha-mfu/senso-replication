# WP6 deviations and implementation notes

`papers/paper1/wp6-deviations-log.md`. Design: `papers/paper1/wp6-harm-design.md` (tag `wp6-prereg`). Mirror: `experiments/paper1_ontology_manifests/results/real_v2/wp6/wp6_deviations.json`.

Every entry was decided on 2026-10-09, **after `wp6-prereg`, before `wp6-generator-freeze` and before `wp6-run-freeze`**, and **without knowledge of any outcome by condition** (no WP6 run other than the 16-run development pilot exists, and the pilot is not analysed). Entries marked *(note)* are places where the design is silent and the implementation had to choose; they are not departures.

| # | What | Why | Expected impact |
|---|---|---|---|
| 1 | `wp6/runner.py` re-implements the orchestration loop of `wp5.runner.run_all` instead of calling it. Everything else is reused unchanged (`agent.run_agent`, `conditions.condition_text`, `evaluate.evaluate_diff`, `ledgers` format, `runner.ensure_env/schedule/is_infra/load_valid`). `wp5/*` is untouched. | The venv reset has to happen inside the per-task loop, which in `wp5.runner` is a closure that cannot be hooked without editing frozen WP5 code. | None on behaviour; same schedule rule, retries and checkpoints. |
| 2 | The venv reset is done by restoring a pristine copy of the freshly built venv (`.v_golden`, same absolute path) and clearing the agent's `HOME`, **before every agent run and again before the evaluation of that run's patch**. `uv pip freeze` is hashed before and after each agent episode (Y7). The design text says "hash and rebuild after any change"; the coordinator decision says "reset before every run"; both are done (reset always, hash for Y7). | Coordinator decision; copying is seconds, rebuilding is 20 to 90 s per run (about 25 % more wall time). Evaluating in the pristine venv means a package that only the agent installed cannot make a patch pass or fail. | In WP5 the evaluation ran in the (possibly mutated) shared venv; WP6 resolve rates are therefore evaluated under the same environment for every run. |
| 3 | A false dependency line carries **no version specifier** (`httpx`, not `httpx>=...`); true lines keep the declared specifier verbatim. | Design 2.2 gives no specifier for the competitor. Copying the replaced dependency's specifier produced nonsense such as `toolz^0.109.2`. | The length of F lines differs by a few characters; a bare name is also a valid T line (unversioned declarations exist). |
| 4 | *(finding, needs a decision)* The WP5 tasks are small repositories, so the T manifests are far shorter than the design estimate (median 299 characters and 11 claims, against 1.0 to 1.6 k and 19), and **a falsification slot can often not be filled**. Rule applied as designed: an unfillable slot is dropped from **all** manifests of the task. Result for the 80 tasks (superseded by deviation 13): kind 1 filled in 34, kind 2 in 29, kind 3 in 34, kind 4 in 43; mean false claims per F manifest 1.75 (0: 14 tasks, 1: 25, 2: 16, 3: 17, 4: 8); in 14 tasks F_R and F_I equal T. Causes: no non-gold, non-test layout entry (45 tasks), fewer than 3 key-file directories (51), no true test command (33: `pytest --collect-only <root>` rc 2 in 17 tasks because a few test modules fail to import and rc 3 or 5 in 2; pytest signature not supported in 12 by the re-check and in 1 by HermiT, entry 8; no test root in 1), no declared dependency imported by a non-test file (27) or none outside the gold files (10), a `make` target that the checker cannot contradict (14). 30 of 80 tasks exceed the 5 % length rule (`length_violation_*`, covariate SA4). | The 4-of-19 dose is a deliberate coordinator decision; the implementation cannot reach it on these repositories. | The dose varies from 0 to 4 per task. H1 to H4 have less power than designed; `n_false` and `kind` must enter the analysis as covariates, or the rule must change (options in the final report). No code path was changed to hide it. |
| 5 | *(note)* Operational definitions where the design is silent: **package directory** = a directory with at least one non-test source module of its own (excluding `MODULE_ROOT_EXCLUDED` names and hidden/egg-info directories); **gold area** = directories that contain a gold-touched file, so an **unrelated** layout entry is one with no gold file under it; **gold package** for F_I's removed file = the depth-1 component of the gold directories; **test root** = the shallowest ancestor named test/tests/testing of the most test files (else the repository root); **key files** rank the listed non-test directories by number of source modules in the subtree and take the largest file of each (no file twice); **runtime dependencies** = declared Python distributions that are installed in the task venv and imported by at least one non-test source file outside `MODULE_ROOT_EXCLUDED` (deny list in `wp6.yaml`: python, pip, setuptools, wheel, build backends), ranked by importing files; import names come from the venv's distribution metadata; **Python line** = `>=` lower bound of `requires-python` / `python_requires` (or `^`/`~` bound), kept only if the re-check says Supported. | Needed to make the generator mechanical. | Layout, key-file and dependency choices are deterministic given the base tree and the pinned task venv. |
| 6 | *(note)* Extra uniqueness constraints: the make-target regex must also have zero `git grep` hits in the base tree (a README line "make test" would make a hit unattributable); a fake dependency must additionally be absent from the declared dependencies; every false token is audited after generation (`token_audit` in the manifests index: 280 tokens, 0 failing). Path names are checked against path components and the issue text; they are not required to be absent from file contents (the vocabulary words `core`, `internal`, ... occur in many files, so counterfactual T/A hits are expected and are what the counterfactual baseline measures). | Design 2.2 constraints, applied literally and one step further for commands. | Fewer fillable make targets (kind 3). |
| 7 | *(note)* Verification split over two venvs: the generator, the re-check (instrument 2) and the runtime probes run in the WP5 run venv; HermiT (instrument 1, owlready2) runs in the project venv (`wp6/hermit_worker.py`, reads the measured claims as JSON and builds the ABox). **One ABox per task** holds the union of the distinct claims of T, F_R and F_I (a claim's verdict does not depend on the manifest it sits in), not one per manifest. | owlready2 is not installed in the run venv. | None on verdicts. |

| 10 | *(note)* Trajectory parser: in the WP5 logs a response that the harness rejected is **not stored** as an assistant message (only the following format-error user message is), so "assistant message followed by a format-error or output-limit message" never occurs there; the rule is implemented anyway. | 13 | **Add mode** (author decision after the dose shortfall in deviation 4; decided before the generator freeze, with no outcome data). Replacement is kept wherever a slot can be filled (no change there). When it cannot, the false line is ADDED to the matching section of F_R and F_I and T is left unchanged for that slot. Kind 1: base directory is the gold dir for F_R and the unrelated listed dir for F_I; without a filler entry, or without an unrelated listed directory, F_I uses any non-gold, non-test, non-hidden base-tree directory with no gold file below it (shallow first), else the repository root. Kind 2: F_R widens gold dir, then top package, then anywhere; F_I stays outside the gold package; if the history has no deleted `.py` file the slot stays empty; the never-existed-name fallback of the old rule is kept for the case that deleted files exist but none fits. Kind 3: a `make <target>` line may be added when the task has no true command line; it must pass the same gate. Kind 4: a competitor (or a generic fallback name) of a declared dependency is added when no dependency line can be replaced. The mode is recorded per claim (`mode` in the claim, `modes` and `false_claims` in `wp6_manifests_index.json`). | Deviation 4: mean 1.75 false claims per F manifest, 14 tasks with F equal to T. | Dose after: 52 tasks with 4 false claims, 27 with 3, 1 with 2, none with 0 (mean 3.64; before 8, 17, 16, 25, 14 for 4, 3, 2, 1, 0). False claims: 291 per arm, F_R 150 replace / 141 add, F_I 162 replace / 129 add. F is now longer than T in most tasks (median +13 % F_R, +11 % F_I, range -15 % to +130 %); 66 of 80 tasks exceed the 5 % length rule (covariate SA4). Add-mode lines are not hidden among T lines of the same slot, so H3 and H4 contrasts mix replace and add claims; the analysis records `mode` and has a replace-only sensitivity (SA10). |

| 17 | `wp6_power.json` (design 5) is computed by `wp6/power.py` with the realised dose, using a repository-cluster paired t test as a fast stand-in for the GEE (2,000 replicates per cell; hit uptake q per false claim, T rate 0.01; Poisson wasted steps with task mean 0.37 and paired SD about 0.7; resolve p0 from the WP5 A runs).
