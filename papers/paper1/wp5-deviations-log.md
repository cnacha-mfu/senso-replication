## 14. Shared task virtual environment across runs (found 2026-10-09, after the analysis)
- **What:** `runner.py` built one uv venv per task and ran all units of that task in it sequentially; `clean_repo` reset the git checkout but not the venv. A package installed by the agent in one run (via the `pip` shim) remained available to later runs of the same task.
- **Found by:** the WP6 design review (papers/paper1/wp6-harm-design.md).
- **Impact:** run order within a task was shuffled with a seeded RNG (`runner.py`, plan 2.3), so carry-over is not aligned with condition; it adds noise rather than a systematic bias. The number of runs that installed packages will be counted from the trajectories and reported.
- **Action:** disclosed as a threat to internal validity in the paper; WP6 resets the venv before every run. No WP5 result is changed.
